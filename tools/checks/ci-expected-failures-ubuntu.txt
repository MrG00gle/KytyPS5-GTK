# The tests that fail only in the ubuntu and coverage CI jobs (Ubuntu 24.04), on that release's
# software Vulkan driver (tools/checks/junit_check.py --expected-failures, given after
# ci-expected-failures.txt; docs/testing.md). One "<test name> <exact failure text>" per line.
#
# Ubuntu 24.04's lavapipe (Mesa 25.2.8) lacks imageViewMinLod and depthBounds, so the Emulator's
# Vulkan device selection rejects it and each test below, which creates a Vulkan window, stops.
# Mesa 26.2 (Fedora) has both, and the tests must pass there. The repository owner approved this
# policy for exactly the tests below: kernel_file_system on 2026-11-13, and pm4_flip,
# video_out_flip_rate, and device_creation on 2026-11-24. CI still runs them unfiltered in every
# job, and on Ubuntu a listed test is accepted only when it fails with exactly the text given here.
# It fails CI when it fails for another reason, is skipped, or passes (then remove it from this
# list). Only the ubuntu and coverage jobs pass this file; tools/checks/workflow_check.py checks
# that, and that the file holds exactly these entries.
kernel_file_system llvmpipe (LLVM 20.1.2, 256 bits): image view minLod is not supported; depthBounds is not supported
pm4_flip llvmpipe (LLVM 20.1.2, 256 bits): image view minLod is not supported; depthBounds is not supported
video_out_flip_rate llvmpipe (LLVM 20.1.2, 256 bits): image view minLod is not supported; depthBounds is not supported
device_creation llvmpipe (LLVM 20.1.2, 256 bits): image view minLod is not supported; depthBounds is not supported
